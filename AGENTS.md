# agent-qa-harness-template - Agent Rules

Binding rules for any Claude (or human) working in this repo. Mirrors the structure of the Ballpark agent rules so it reads familiar; the content is template-specific.

## TL;DR - top things to know

1. **This is a template, not a product.** Code here ships to other repos via `gh repo create --template`. Every assumption about a specific app stack (Hebrew, Supabase, Vercel, a particular auth provider) belongs in `docs/CUSTOMIZATION.md` or `examples/*`, not in the top-level shell.
2. **The shell stays project-agnostic.** Journey IDs in the stub spec (`J1`-`J4`) are placeholders. Hebrew is mentioned only in the Ballpark worked example. Use "locale" terminology generally.
3. **The brain lives in `scripts/`.** `multi-model-dispatch.ts`, `dedup-findings.ts`, `generate-report.ts`. Today they are thorough stubs. Filling them in is the next session's priority work.
4. **JSON output is locked in.** The per-step output schema is decided. Do not change it without a `DECISIONS.md` entry explaining why and migrating consumers.
5. **No project secrets in this repo.** Adapter files generated by `scripts/scaffold.sh` may reference `.env.local` in the consuming project, but no `.env*` files are committed here.

## What this template targets

- Frameworks: Next.js App Router (primary), SvelteKit, Astro, Nuxt
- Auth: Clerk, Supabase, Auth0
- DB: Postgres (Neon or Supabase), Cloudflare D1, MongoDB
- Hosting: Vercel (primary), Cloudflare Workers

Adding a new framework or auth provider means a `docs/CUSTOMIZATION.md` section plus an example directory. The journey harness itself does not change.

## Engineering principles

1. **Browser is a dumb client to the harness.** Playwright drives, helpers capture, scripts decide. Never let assertion logic leak into the journey spec file beyond the structural shape (capture, push finding, expect status not fail). Judgment belongs to the multi-model dispatcher.
2. **Structured first, prose second.** Every per-step finding emits JSON conforming to the schema in `docs/PHILOSOPHY.md`. Markdown reports are a rendering of that JSON, not a source of truth.
3. **Cheap signal beats no signal.** A flaky journey that catches one real bug per month is worth running. Disable individual flaky steps with `// flake: <reason>` and keep the journey green. Do not delete a journey because of flake.
4. **Run by default, opt-out for cost.** The scaffolder wires CI to run the no-auth static journey on every PR. Heavy multi-model dispatch is a cron or manual invocation, not a per-commit gate.
5. **Findings dedup deterministically.** The dedup key is (`journey_id`, `step_id`, `severity_bucket`, normalized title). Same input must produce the same dedup outcome. Surface model disagreements as their own report section, not by suppression.
6. **Auth fixtures are secrets.** `tests/e2e/fixtures/*.json` is gitignored. A leaked storageState file is a leaked session cookie. Treat with the same hygiene as `.env.local`.
7. **The OpenRouter key is not optional.** Cross-provider second opinions are a load-bearing part of the dedup story (provider-family blind spots). The dispatcher fails loud if `OPENROUTER_API_KEY` is unset and a non-Anthropic model is requested.

## Orchestration model (when run from Claude Code)

The template ships with a single Claude skill (`.claude/skills/agent-qa-harness/`). Invoking it does three things:

1. Calls `gh repo create --template yhyatt/agent-qa-harness-template ...`
2. Clones the new repo to a sibling directory
3. Runs `./scripts/scaffold.sh` interactively, then prints the next-step checklist

This skill is intentionally narrow. Multi-model dispatch, journey authoring, and report rendering are normal Claude Code workflows in the consuming repo, not skill territory.

## Style guide (binding)

- **No em-dashes anywhere.** Use a comma, period, or colon. This is enforced on shipped strings (user-visible text in reports, journey titles, finding bodies). Code comments and markdown prose may use hyphens but never em-dashes.
- **No en-dashes or `--` as casual punctuation.** Same rule.
- **No emojis** unless Yonatan adds them later.
- **Lowercase headings inside body text.** Markdown headers can be Title Case. Prose stays flat.
- **Imperative commit messages, scoped.** Allowed scopes: `scaffold:`, `harness:`, `docs:`, `scripts:`, `chore:`, `fix:`.
- **Project-agnostic everywhere except `examples/`.** Hebrew goes in the Ballpark example only. Same for any other locale-specific or stack-specific detail.

## Env vars consumed by this repo

```
TEST_TARGET_URL=https://app.example.com    # the URL to walk
ANTHROPIC_API_KEY=...                       # for dispatch
OPENROUTER_API_KEY=...                      # for cross-provider opinions
QA_AUTH_FIXTURE_PATH=tests/e2e/fixtures/host-auth.json   # optional override
```

The template never reads project-specific env vars (`SUPABASE_*`, `CLERK_*`, etc). Adapter files generated by `scripts/scaffold.sh` may. The boundary matters.

## Workflow conventions

- Branch naming: `harness/<topic>` for harness work, `docs/<topic>` for docs.
- Initial commit per branch should explain the slice in the body, not just the title.
- Do not merge a branch that lowers test coverage of journeys; add a journey for every new flow.
- Examples directory is intentionally sparse. Add an example only when a real project has wet-run validated the stack.

## Local development env (Claude Code)

This repo ships its own skill at `.claude/skills/agent-qa-harness/`. Claude Code has a known bug where any project `.claude/skills/` directory shadows the global `~/.claude/skills/` entirely (see github.com/anthropics/claude-code/issues/44207). The workaround for local development is to symlink globals into the project skills dir:

```bash
mkdir -p .claude/skills
for s in ~/.claude/skills/*/; do ln -sfn "$s" ".claude/skills/$(basename "$s")"; done
```

The `.gitignore` excludes `.claude/skills/` so the symlinks are local-only. The committed `agent-qa-harness/` subdirectory inside `.claude/skills/` is a regular directory, not a symlink, and is the one published with the template.

## Orchestration (when implementing this repo)

The template repo itself follows the same slice routine Ballpark uses:

1. Each slice runs as a chain of subagents from the main session. Orchestrator routes, briefs, reviews, decides. Heavy code work goes to a worktree subagent.
2. Implementation subagent runs with `isolation: "worktree"` on a feature branch like `slice-N-<topic>`. Brief includes scope, hard rules from this file, and a green gate (typecheck before reporting back). The impl agent does not push.
3. Review subagent (Opus 4.7, read-only) reviews the diff in the main worktree, writes findings to `.audit-<date>/REVIEW-<topic>.md`.
4. Orchestrator opens the PR with `gh pr create`. Never direct-merge to `main`.
5. After every push, schedule a 10-minute remote agent to pull PR review state. Reply inline to every bot comment with the fixup SHA. Invoke `@codex review` explicitly after each fixup push (Copilot auto-re-reviews; Codex does not).
6. Persistent artifacts (audits, reviews, impl notes, research outputs) live in `.<kind>-<topic>/` directories at the repo root, gitignored. Never `/tmp`.

## Out of scope for v1

- Automatic GitHub issue creation from findings. Deferred until signal-to-noise is measured on real runs.
- Visual regression beyond what axe-core catches. Pixel-diff is a separate problem.
- Mobile native (React Native, Capacitor). Playwright is web-first.
- Load testing. This is a correctness harness, not a perf harness.

See `docs/DECISIONS.md` for the reasoning on each item above.
